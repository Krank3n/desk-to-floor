# DECISIONS.md

One line per decision. Never re-litigate; supersede with a new dated entry.

- **2026-08-21** Expo SDK 57 / RN 0.86 / React 19.2, managed workflow + `expo prebuild` in CI. Latest stable at kickoff; template pins kept.
- **2026-08-21** Android-only v1. No iOS build, no react-native-web — smaller dependency surface, faster CI.
- **2026-08-21** Dark-only UI in v1 (`userInterfaceStyle: "dark"`). The app is a filming rig used mid-workout; one theme, no switching logic.
- **2026-08-21** Android package `com.hansendev.desktofloor`; app slug `desk-to-floor`.
- **2026-08-21** Screens live in `src/screens/`, routes in `src/app/` are one-line re-exports — screens stay testable without router context.
- **2026-08-21** Domain logic goes in `src/lib/` as pure TypeScript, UI-free, so unit tests carry most of the confidence and CI stays fast.
- **2026-08-21** Release APKs are debug-signed (Expo prebuild default). Fine for sideloading; no signing secrets in CI. Revisit only if Play Store ever matters.
- **2026-08-21** CI order per plan: checks → APK build → Maestro smoke → nightly release. A build that fails the smoke test is never published.
- **2026-08-21** Rolling GitHub release tagged `nightly`, asset `desk-to-floor-nightly.apk`, `--clobber` on every green main push.
- **2026-08-21** Emulator job: API 34 x86_64, pixel_6 profile, KVM on ubuntu-latest, no AVD snapshot caching yet (add only if boot time hurts).
- **2026-08-21** Template's React Compiler experiment and typed-routes disabled — fewer moving parts in Jest and CI typecheck.
- **2026-08-21** Event-log timestamps are milliseconds relative to session start (monotonic), with one absolute `startedAt` anchor — see EVENTLOG.md.
- **2026-08-21** `versionCode` bumped manually in app.json when user-visible changes ship, so sideloaded upgrades install cleanly.
- **2026-08-21** Session ids are sortable timestamp+random (`20260821T093000-4f2a9c`), not uuid — human-skimmable filenames beat RFC purity here.
- **2026-08-21** Pausing freezes the phase timer but the session clock keeps rolling; pauses are events. Keeps the log aligned with continuously-rolling video (M2) — the pipeline cuts paused spans.
- **2026-08-21** The End button ends immediately, no confirm dialog — fewest taps mid-floor; the log is saved either way, and a wrong tap costs nothing.
- **2026-08-21** Session storage uses the `expo-file-system/legacy` API — stable, documented surface; migrate to the object API only if legacy is removed.
- **2026-08-21** Player logic is a pure state machine (`src/lib/player.ts`); the screen owns only a setInterval and TTS side effects. Real elapsed time, not tick counts.
- **2026-08-21** Nightly cloud routine `trig_019k2i2bLjLAb2vp2GB19Bjs`: cron `0 16 * * *` UTC (2am AEST, drifts to 3am during AEDT — accepted), model claude-sonnet-5, no MCP connectors. Manage at https://claude.ai/code/routines.
- **2026-08-21** Nightly routine has a standing billing guard: if Actions jobs fail to start with the account-billing error, it comments once on the FEEDBACK billing issue and stops instead of retrying.
- **2026-08-21** Repo made PUBLIC (owner's call, supersedes the kickoff's private default) — Actions minutes are free on public repos, which unblocks CI and the nightly APK loop at zero cost. Consequence: code and roadmap are visible; never commit anything sensitive (already rule 5 in CLAUDE.md).
- **2026-08-21** Recording defaults: front camera, audio ON (talking to camera is content; music mode replaces audio in post), "Record video" toggle defaults on, camera preview doubles as the framing aid on the pre-session screen.
- **2026-08-21** `recording.startOffsetMs` is when the app *asked* the camera to record, not true frame 0 — camera-start latency (~100–300 ms) is absorbed by edit handles, not measured. Revisit only if beat-sync (M3/M4) proves it matters.
- **2026-08-21** Screen keep-awake during workout sessions (expo-keep-awake) — a sleeping screen would kill the recording mid-session.
- **2026-08-21** Music tracks are user-picked local files copied into app storage (expo-document-picker + expo-audio). No bundled audio: rule 5 forbids committing media, and no external services in v1.
- **2026-08-21** Music mode only ever *stretches* an interval to the next 8-count, never shortens one — losing prescribed work time to the beat is the wrong trade at 39.
- **2026-08-21** Player phase ends are computed in session-time arithmetic (`phaseEndSessionMs`), not by accumulating ticks — required for exact phrase snapping, and pause-proof.
- **2026-08-21** Pause re-anchors the beat grid by the paused duration (music pauses with the workout); the editor reconstructs the shift from pause/resume events rather than the log carrying a second anchor.
- **2026-08-21** Music playback does not loop — a loop restart would desync phrase alignment from the extrapolated grid. Track ends, music stops, session continues.
- **2026-08-23** The pipeline lives in `pipeline/` but inside the ROOT npm project (supersedes the kickoff's `npm --prefix pipeline` sketch) — one lockfile, one toolchain, one CI install step. Rule 1 is keeping CI green; a second package is a second thing to break.
- **2026-08-23** The pipeline imports the app's `src/lib` directly (event log types, exercise library) rather than duplicating them. The schema is the contract; a copy would drift silently.
- **2026-08-23** Auto-editor split: pure planner (`edl.ts`) → pure arg builders (`ffmpeg.ts`) → thin executor (`run.ts`). Every editing rule is unit-testable with no video, so CI never needs ffmpeg.
- **2026-08-23** One-pass ffmpeg (trim + concat + drawtext in a single filter graph), no intermediate files. Sessions are ~10–15 segments; revisit only if a graph gets unwieldy.
- **2026-08-23** Music-mode cuts round INWARD to the beat (start up, end down) — never outward, which would bleed into a rest or a paused stretch.
- **2026-08-23** Handles (250 ms) apply only outside music mode; in music mode the beat *is* the intended edit point and already absorbs camera latency.
- **2026-08-23** Shorts are cut only from toprock/footwork/freeze moves — the breaking content is what the channel's Shorts are for; wrist prep is not a hook.
- **2026-08-23** drawtext apostrophes are replaced with typographic ’ rather than fighting ffmpeg's nested quoting. Looks better and removes an escaping failure mode.
- **2026-08-21** Filling the event log's `music` placeholder is NOT a schema bump (EVENTLOG.md pre-authorised it at kickoff and no consumer has shipped) — reasoning recorded in EVENTLOG.md's version history rather than inflating to v2.
- **2026-08-25** `training-log.ts` computes actual work time with its own small pause-span helper rather than importing `pipeline/src/edl.ts`'s — the pipeline depends on `src/lib`, never the other way, so duplicating ~10 lines of pure arithmetic beat inverting that dependency for one function.
- **2026-08-25** `formatTrainingLog` orders sessions oldest-first — the M5 coach prompt reads as a progression story, not a most-recent-first feed.
- **2026-08-25** Nightly routine config corrected (SUPERSEDES the 2026-08-21 entry above). Its first four scheduled runs, 21–24 Aug, all died silently: sandbox came up, repo cloned, "Claude Code process started", then no `init` event and no work — no error surfaced anywhere. Restoring the working config took two changes at once: `allowed_tools` must include `preset:default` (the original hand-written list of six tools did not), and the environment moved to `env_01L3yneP3NEZ94iXTHJKsiek`. Both were changed together, so which one was fatal is not isolated — if the routine ever dies this way again, suspect the tool preset first.
- **2026-08-25** Coach model is `claude-opus-5` with adaptive thinking and `effort: high`. Programming a week off a training log is reasoning work, and it runs a few times a week at most — the wrong call here costs a wrist, not a token budget.
- **2026-08-25** The app calls the Anthropic API **directly from the device** with the owner's own key in the platform keystore. Acceptable because this is a single-user app on his own phone and v1 has no server. If Desk to Floor is ever distributed to anyone else this must move behind a proxy — a shipped key is a leaked key.
- **2026-08-25** Coach responses are validated in code, not trusted from the prompt (`coach-plan.ts`): unknown move ids dropped and surfaced, wrist prep forced first, durations clamped, unusable responses rejected. A prompt rail is a request; this is the enforcement.
- **2026-08-25** The coach may only prescribe ids from the existing exercise library — it cannot invent moves. Keeps every prescription something the app can actually run, cue, and film.
- **2026-08-25** The generated week is stored as move ids + durations, never serialized Exercise objects, so library edits flow through on load instead of leaving stale copies.
- **2026-08-25** The coach calls the Messages API over plain `fetch`, NOT `@anthropic-ai/sdk` (which was tried first and removed). The official SDK is Node-targeted: its credential chain imports `node:fs`, which Metro cannot resolve, so the release bundle fails outright — CI caught it in `createBundleReleaseJsAndAssets`. It ships no `react-native` export condition and its `browser` field only remaps two unrelated tool files. One endpoint, one POST; revisit if an RN-supported SDK ships.
- **2026-08-25** Adding a dependency now requires `npm run bundle` before pushing. typecheck/lint/tests all run in Node where `node:*` resolves fine, and `expo prebuild` doesn't bundle JS — Metro is the only check that catches this, and without it the failure surfaces in CI minutes later.
- **2026-08-25** A routine that fires but does nothing looks identical to a healthy one from the repo side (no commits could just mean "nothing to do"). Check `last_fired_at` against actual commits when a night passes with no BUILDLOG entry.
- **2026-08-25** `progression.ts` bases each move's signal on only its *most recent* logged occurrence, not a rolling window — matches how the coach system prompt already frames things ("previous session"), and keeps the rule simple enough to state in one sentence per case rather than tuning a streak length.
- **2026-08-25** Progression delta magnitude is ~15% of the move's planned work seconds, rounded to the nearest 5s with a 5s floor — coarse enough to survive rounding, small enough that a bad suggestion costs one session, not a setback.
- **2026-08-25** Computed progression signals are handed to the coach as a floor it may deviate from with reasoning (`notes` must explain any deviation), not a hard code-enforced clamp like the wrist-prep/move-id/duration rails in `coach-plan.ts` — progression calls are judgement, not safety, so the enforcement point stays at "explain yourself," not "can't happen."
- **2026-08-26** Reference clips live at `<documentDirectory>/reference-clips/ref-<moveId>.mp4`, a separate store from `session-store.ts` — one clip per move, overwritten on retake, persisting across sessions instead of accumulating one-per-workout like footage does.
- **2026-08-26** `expo-video` (`~57.0.2`, matched to the SDK) is a new dependency, used only for local on-device playback (`VideoView` + `useNativeControls`, no `player.*` property mutation — its config plugin is left off app.json since we use neither background playback nor picture-in-picture, both of which default to off).
- **2026-08-26** The move list (`moves-screen.tsx`) uses a `ScrollView` + `.map`, not `FlatList`: `FlatList`'s windowed rendering only mounts `initialNumToRender` rows, which silently broke "assert every exercise renders" in tests; the list is small and static, so virtualization buys nothing.
- **2026-08-26** `move-detail-screen.tsx` enforces a 1.2s minimum recording duration before calling `stopRecording()`: CI's Maestro flow tapped Start then Stop back-to-back and failed — `recordAsync()` never resolved to a usable file, because stopping the camera the instant it starts is a native-layer race, not just a test artifact. A near-zero-length reference clip is useless anyway, so the floor is enforced for real usage too, not only to un-flake CI.
- **2026-08-26** CI's `build-apk` job sets `org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m` by appending to the prebuild-generated `android/gradle.properties` (that directory is gitignored and regenerated every run, so this can't live as a committed file edit). Added after `:app:mergeDexRelease` hit `OutOfMemoryError: Java heap space` on the default heap — `expo-video`'s native module pushed the app's dex count past what the default Gradle/D8 worker heap handles. Appending after prebuild, not editing `app.json` or adding a config plugin, since there's no Expo-level field for this and the duplicate key simply wins on read.
- **2026-08-26** The append above uses `printf '\n%s\n' ... >>`, not a bare `echo ... >>`: `expo prebuild`'s generated `gradle.properties` ends with **no trailing newline**, so a plain `echo >>` glues straight onto the last property's value instead of starting a new line — corrupted `expo.inlineModules.watchedDirectories=[]` into `...=[]org.gradle.jvmargs=...` and broke a node subprocess the Expo Gradle plugin runs during project configuration (`Process 'command 'node'' finished with non-zero exit value 1`, no useful message). Cost one extra red run to catch; verified by regenerating the file locally and parsing it before trusting the fix.
- **2026-08-26** `.maestro/moves.yaml` does NOT wait for a full record → save → retake round trip, even with the 1.2s minimum-recording-duration floor in place: four straight CI runs stalled on "Retake" never appearing after Stop recording (with a 20s wait, plenty of margin for a real device), pointing at the emulator's virtual front camera not reliably producing a playable file in headless CI rather than an app bug. The flow now only proves the real wiring — permissions, navigation, CameraView mounting, a real `recordAsync()` call starting — matching the precedent in `coach.yaml` (skips the billed API call) and `music.yaml` (skips the system document picker): don't make a Maestro flow depend on native behavior that's unreliable in CI. The save/retake state machine itself is already covered by `move-detail-screen.test.tsx` with a mocked camera.
- **2026-08-27** Progress stats (`progress-stats.ts`) tracks a fixed, curated set of four moves (wrist rocks, deep squat hold, crow hold, six-step half speed) rather than every logged move, and uses `actualWorkSeconds` from `training-log.ts` — time actually on task per move — as the proxy for the roadmap's named metrics (wrist range, squat hold, crow hold, 6-step tempo). There is no sensor for range of motion or footwork tempo in a phone-camera-only app; time-on-task is the one metric already computed, tested, and available for every move without new instrumentation or an event-log schema change. Revisit if a future milestone adds real measurement (e.g. pose estimation on the recorded footage).
- **2026-08-28** Export presets (`pipeline/src/presets.ts`) ship as exactly three named bundles — `default` (unchanged prior behaviour), `draft` (fast/low-quality, longform only, for checking cuts), `upload` (slow/high-quality, longform + Shorts, for the render that gets posted) — rather than exposing raw `--crf`/`--preset`/etc. flags on the CLI. The pipeline has one operator (the owner, from a terminal); three named intents cover what he'd actually reach for, and a typo'd `--preset` name fails loudly (`resolvePreset` lists the valid names) instead of silently falling back. `--no-shorts` always overrides a preset's Shorts default, and `--font` always layers on top, since those are orthogonal to encode quality.
